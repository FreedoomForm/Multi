  2417→**Risks:**
  2418→1. **GPTQ `err_block` formula** (line 122): `err_block = (W_block - W[:, i:i_end]) / Hinv_sqrt[i:i_end, i:i_end].diag().unsqueeze(0)`. But by this point `W[:, i:i_end]` has already been overwritten with `q_g * s.unsqueeze(-1)` (line 118). So `W_block - W[:, i:i_end] = 0` → `err_block = 0` → no error propagation. **THIS IS A BUG**. This breaks GPTQ's error-correction property — quantization degenerates to RTN-with-bad-rounding.
